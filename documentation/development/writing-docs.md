# Documentation format

Write VM usage, build, interface, and learning guides in Markdown here.
Language guides live in neo/documentation/. Working context and research
remain in the external mind directory and are not release artifacts.

Describe verified behavior and limits. Distinguish implementation from
proposals. Keep relative links valid in a standalone checkout. The whitepaper
is a preserved design reference. Do not silently update it during cleanup.

C public interfaces should explain ownership, failure outputs, rights, and
lifetime. Keep formal guides alongside the code and avoid duplicating retired
interfaces. Generated manuals belong outside the source snapshot.
